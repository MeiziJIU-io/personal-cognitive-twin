# 基础桌面窗口

退出旧采集/分析程序后双击 update.cmd 更新，再双击 **open-app.cmd**。复用当前 Python 虚拟环境，无需重装工程；环境不存在时启动入口会调用 tools/setup.cmd 安装依赖。窗口用 Python 标准 Tkinter，官方 Windows Python 安装默认包含；目前是窗口启动器，不是无需 Python 的独立 EXE 安装包。

1. **保存目录**：输入绝对路径或点“选择”。设置会记住；旧数据不会随修改路径自动移动。可切回原目录查看。采集期间路径输入锁定。
2. **开始采集并隐藏**：新建独立会话，确认采集进程启动后隐藏窗口。右键蓝色托盘图标 → “打开主窗口”恢复。托盘也可暂停/阅读模式/退出。主窗口“停止采集”会正常停止并保存、生成 ZIP，不强行杀死采集进程。
3. **查看文件**：列表可选择批次，支持“打开批次文件夹”“查看结果”；结果未生成时会提示。保存根目录的 index.html 仍可使用。
4. **开始分析**：选择一个或多个批次，选择模型方式，点击“开始分析所选批次”。运行日志显示事件进度和错误；停止分析保留未完成队列，之后可继续。采集和分析分别控制，开始采集不会自动上传或调用 API。

### 本地 Ollama

默认地址 `http://127.0.0.1:11434/api/chat`，模型 `collector-qwen:16k`。Ollama 必须已经运行，模型须支持视觉。使用 16K 上下文、关闭思考的原生接口。

### API

选择“API（OpenAI 兼容）”，填写完整 Chat Completions URL，例如 `https://服务商/v1/chat/completions`、支持图片和 JSON 输出的模型名，以及 API Key。不同服务商的兼容程度可能不同；不支持 JSON object 或 image_url 的接口会报错，窗口显示错误。此入口不支持 Anthropic 原生 Messages 或 OpenAI Responses 协议。

API 分析会发送所选批次的界面文字和截图到指定服务，数据库同步是另一项功能。密钥仅当前窗口内存及分析子进程使用，不写入设置文件、不放命令行。关闭软件后需重新填写。API 模式不发送 Ollama 专用的 think/num_ctx 参数。

本机 LM Studio 等也可以使用 API 模式及 loopback HTTP 地址；远程接口必须为 HTTPS。重定向不自动跟随。输入地址不能携带用户名或密码。

### 生命周期

采集时点窗口右上角 × 会隐藏，托盘可恢复；只有分析运行时 × 会最小化到任务栏。要真正退出用“退出软件”：停止采集、保存数据，终止分析进程，未完成记录继续保留。正在运行时不要用任务管理器强制结束。

设置保存在工程目录 desktop-settings.json（Git 忽略）；密钥不保存。窗口启动异常记录 desktop-error.log。修改设置不会改变已运行任务，它们继续使用启动时配置。

GUI 中的分析会处理所选批次当前已有的待处理记录，不是持续监控模式；若同时采集，新记录可稍后再次点击分析。GUI 的结束保存不自动执行线上同步，上传仍使用 tools\sync-online.cmd。

### 验证

自动测试覆盖 API 请求中的图像编码、结果入库、无效地址拒绝、设置不加载密钥，并回归采集/传输相关测试。当前云端没有图形显示服务，Tk 窗口创建尝试因无 DISPLAY 失败；无法在此验证实际窗口布局或 Windows 托盘，需要在 Windows 验收：启动隐藏→托盘恢复→停止保存→打开批次→本地/API 分析→停止退出。
