# 个人认知孪生（开源）工程方案 v0.1

Nov 6, 2026 · @Yao

## 1. 产品定位与设计原则

结论：做一个**本地优先、个人持有**的开源孪生框架（暂名 Mirrorself），目标是复刻一切能从已有数据中学到的个人特征：表达风格、行为决策模式、偏好、注意力节律、性格与价值观。其中“给定情境与选择集，预测下一步决策”是最可验证的主轴，其余维度围绕它联合学习。Demo 先用你自己 2–4 周的电脑 + 手机数据跑通 N=1 闭环；AION 的 B2B 社会模拟平台作为闭源上层，建立在这个开源核心之上。

五条设计原则：

- **行为驱动，不是自述驱动。** 训练信号来自“情境 → 选择集 → 实际行为”，量表、访谈、经验抽样只做验证标签。
- **区分曝光与偏好。** 每个决策点同时记录选择集和推送来源（通知、推荐流），否则模型学到的是算法而不是你。
- **分层孪生。** base 模型 → 群体校准层 → 人口学层 → 个体层，每层一个独立 LoRA，只学相对上一层的偏离；关掉个体层就是你自己构建的对照基线。
- **本地优先、隐私内建。** 原始截图提取完即删，只留结构化事件；涉及他人的内容在本地脱敏后才进入训练；全盘加密。
- **模块化、可替换。** 采集器、解析器、模型、Agent 都是插件，通过统一事件模式和接口连接；任何一层都能单独替换和做消融。

### 复刻维度：学什么、从哪学、怎么验

规则：任何维度都可以复刻，但必须同时有数据源、学习方式和封存评测；没有评测的维度不算复刻成功。性格和价值观不直接拿量表标签去训，而是从行为与表达中隐式学，量表只做验证，否则孪生学到的是你的“自述”，又回到偏好伪装问题。

| 维度 | 具体内容 | 主要数据 | 学习方式 | 怎么验证 |
| --- | --- | --- | --- | --- |
| 表达风格 | 用词、句长、标点、emoji、中英切换；对家人/朋友/工作/公开场合的语气差异 | 你发出的消息、帖子、评论、文档、键盘输入 | 以受众和平台为条件的续写任务 | 熟人盲测辨真假；风格计量分类器 |
| 行为决策模式 | 比价深度、犹豫时长、冲动 vs 计划、拖延、放弃点 | `decision_event`、选择集、停留时长、曝光来源 | 选择预测主任务 + 经典选择模型 | 封存集准确率、对数损失 |
| 偏好与品味 | 内容、商品、音乐、信息源、价格敏感度 | 消费/观看/收藏记录、GDPR 导出 | 偏好排序任务 + 选择模型效用参数（可解释） | 预测下周会点开/购买哪些 |
| 注意力与节律 | 作息、app 切换序列、什么时段刷什么 | 使用时长、切换日志、可穿戴 | 下一事件预测 + 状态模型 | 下一 app、下一时段预测 |
| 性格与价值观 | 大五、价值观、风险偏好、政治立场 | 不设专门数据，从行为和表达中隐式学 | 无直接标签 | 孪生作答量表 vs 你间隔数周后的作答 |
| 社交模式 | 对不同关系的回复速度、主动性、话题选择 | 聊天元数据 + 你自己的回复（不含对方原文） | 以关系类型为条件的生成与预测 | 预测是否回复、回复延迟 |
| 知识与观点 | 你知道什么、对议题怎么看 | 阅读内容、笔记、你的表达 | 知识走 RAG，立场走 LoRA | 新议题观点预测，与你事后回答比对 |
| 矛盾与情境依赖 | 说的和做的不一致，不同场合不同面 | 表达数据与行为数据对照 | 条件化在情境上，不强行统一 | 检查孪生是否保留不一致，而不是平均掉 |

两条边界：线下发生、未数字化的东西学不到，孪生模拟的是“数字生活中的你”；风格复刻越像，冒充风险越大，所以“以你的口吻生成消息”默认只在本机可用，不进入对外接口。

## 2. 双轨路线：预测者与模拟者

结论：孪生按两条并行路线构建，共用采集、事件库、基座和群体/人口学层，但个体层、训练目标、信息集和评测完全分开。**预测者（Track P）** 是第三方判定器，回答“这个人在情境 X 下会怎么做、概率多少”；**模拟者（Track S）** 是主体模拟，回答“我是这个人，此刻我怎么想、怎么做、怎么说”。两者的差距，也就是说的与做的之间的落差，本身就是研究对象。

|  | 预测者（Track P） | 模拟者（Track S） |
| --- | --- | --- |
| 视角 | 第三人称观察者 | 第一人称主体 |
| 能看到的信息 | 一切可用特征：历史统计、人群基率、状态模型输出 | 只有本人当时看到的和记得的 |
| 输出 | 校准过的概率分布 + 依据事件 | 采样出的行为、语言、行动轨迹 |
| 架构 | LLM 读选项 logprob + 经典选择模型 + 元模型集成 | 生成式 LLM + 情景/语义记忆 + 状态 + Agent 循环 |
| 个体层 | `lora-p`：判别式多任务 | `lora-s`：生活流续写 + 偏好优化 |
| 评测 | 对数损失、Brier、校准误差、分场景准确率 | 可区分性、轨迹分布匹配、长时程漂移、自述复现 |
| 典型失败 | 回归均值，变成刻板印象 | 人格漂移、助手人格泄漏、编造记忆、比真人更一致 |
| 主要用途 | 研究接口、调查、决策预测 | 桌面伴侣对话、多智能体社会模拟、反事实推演 |

### 2.1 预测者轨道

数据构造成第三人称样本，可以加入任何有助于预测的特征：

```
[对象画像摘要] [近 30 天同类决策统计：促销期购买占比 0.7]
[情境] 周二 14:32，淘宝，会后 20 分钟，昨夜睡眠 5.2h
[选择集] A ¥299 | B ¥599 | C ¥899 | 不买
[曝光来源] 主动搜索
→ 目标：她的实际选择（训练时读各选项 logprob）
```

- **模型组合**：LLM 给出选项分布；多项/混合 logit 选择模型给出可解释的效用参数；梯度提升树作为强基线；元模型按情境给三者加权。
- **输出**：每个选项的概率、最相似的历史事件 id、相对人口学层的偏离量。
- **防回归均值**：对比学习（区分你和相似人群），并把预测拆成“人群基线 + 个体偏离”两部分单独评估。
- **评测**：封存集上的对数损失和 Brier 分数、校准曲线（ECE）、按场景切片的准确率，对照频率基线和“Base + 人口学提示词”。

### 2.2 模拟者轨道

数据构造成第一人称、按时间排序的生活流，用补全格式训练：

```
14:12 我刚开完会，有点累。
14:20 打开淘宝，搜“降噪耳机”。
14:29 看到 A ¥299、B ¥599、C ¥899。B 的评论还行……
14:32 加入购物车，没下单。
→ 续写：我接下来做什么、想什么、对谁说什么
```

- **信息集隔离（最关键）**：在时间 t 生成时，只能检索 t 之前、本人可见的内容；不给任何聚合统计和派生特征。实现上是带时间截断的“时间旅行检索”，`memory_search` 强制 `ts < t` 且只查原始事件，不查统计表。否则模拟出来的人会比你本人更了解自己、更理性。
- **记忆结构**：情景记忆（事件按时间写入向量库）；语义记忆（定期从你自己的表达中总结“我是谁、我在意什么”，不从统计中生成）；工作记忆（当前状态和最近事件）。
- **Agent 循环**：感知（屏幕上下文）→ 回忆（受限检索）→ 可选的内心独白 → 行动或表达 → 写回情景记忆。
- **训练两步**：先做生活流续写的监督微调；再做偏好优化，奖励来自两处：预测者给出的行为似然（行为要像），以及风格判别器无法区分（语言要像）。用 KL 约束防止奖励投机。
- **防漂移**：长时程运行时，每隔一段用真实的最新事件重新锚定状态；采样温度校准到行为熵与预测者分布一致，保留随机性而不是取众数。
- **评测**：人和分类器都能否区分真假文本；一周模拟轨迹与真实轨迹在 app 序列、作息节律、消费频次上的分布距离；长时程一致性；对同一问题，模拟者的自述是否像你本人的自述。

### 2.3 两条轨道如何互相作用

1. **预测者先行**：它可验证、可校准，是模拟者的裁判和奖励模型。
2. **一致性监控**：模拟者产生的行为放到预测者下算似然，似然持续偏低的场景就是模拟者不可信的区域，在界面上降级或提示。
3. **说与做的落差**：同一问题分别问模拟者（“你会买吗”，得到自述）和预测者（实际购买概率），两者的差值是个体层面偏好伪装的估计；用你本人的自述和真实行为验证这个估计。
4. **产品分工**：研究接口默认走预测者；桌面伴侣用模拟者的口吻说话，但概率和依据来自预测者；AION 的多智能体社会模拟用模拟者。

### 2.4 对其他各章的影响

| 章节 | 预测者 | 模拟者 |
| --- | --- | --- |
| 数据库 | 读 `decision_event`、统计视图 | 新增 `memory_snapshot`（每个时刻可见的记忆范围）、`semantic_memory` |
| 训练 | 个体层 `lora-p` | 个体层 `lora-s` + 偏好优化阶段 |
| Agent | 孪生 Agent 的 `predict` 工具 | 孪生 Agent 的对话与行动生成 |
| API | `/predict`、`/survey` | `/simulate`（轨迹）、`/agent/chat` |
| 评测 | 校准与准确率报告 | 可区分性与漂移报告 + 预测者一致性 |
| Demo | v0.1 完整实现 | v0.1 只做风格续写和伴侣对话，v0.2 完整实现 |

## 4. 模块化组件与仓库结构

采用 monorepo，Python 做数据与模型，TypeScript 做前端；模块之间只通过事件模式（`packages/schema`）和 HTTP/gRPC 接口通信，任何模块可以单独替换。

```
mirrorself/
├─ packages/
│  ├─ schema/          # 事件模式（Pydantic + JSON Schema），全仓唯一真相源
│  ├─ collectors/      # 采集插件，每个一个子包
│  │  ├─ desktop/      # 基于 screenpipe：截图 + OCR + 键鼠/窗口事件
│  │  ├─ android/      # Kotlin App：无障碍服务读 UI 树 + 通知监听
│  │  ├─ ios_lite/     # 屏幕使用时间、快捷指令触发（降级方案）
│  │  ├─ exports/      # GDPR 导出解析器（Google、YouTube、淘宝、微信等）
│  │  └─ wearables/    # 位置、心率、睡眠（Health Connect / 导出文件）
│  ├─ pipeline/        # 处理：去重、OCR/VLM 提取、脱敏、事件切分、时间对齐
│  ├─ store/           # 数据访问层：Postgres + pgvector + 对象存储
│  ├─ state_model/     # 独立状态模型（疲劳、唤醒、社交情境）
│  ├─ trainer/         # 分层 LoRA 训练、数据集构建、时间切分
│  ├─ eval/            # 预测封存、基线对照、消融实验
│  ├─ agents/          # Agent 编排、工具定义、记忆
│  └─ sdk/             # Python/TS 客户端，供外部研究调用孪生
├─ apps/
│  ├─ api/             # FastAPI 后端
│  ├─ worker/          # 异步任务（Celery/Arq）
│  ├─ web/             # Next.js 前端控制台
│  └─ esm/             # 经验抽样小程序（PWA，推送问卷）
├─ deploy/             # docker-compose（单机）、Helm（可选）
└─ docs/
```

| 模块 | 输入 | 输出 | Demo 是否必需 |
| --- | --- | --- | --- |
| collectors/desktop | 屏幕、键鼠 | 原始帧 + OCR 文本 + UI 事件 | 是 |
| collectors/android | 无障碍事件、通知 | 结构化 UI 事件 | 是（若用 Android） |
| collectors/exports | 平台导出 zip | 历史行为事件 | 是 |
| pipeline | 原始数据 | `DecisionEvent`、`ContextEvent` | 是 |
| state\_model | 生理、位置时序 | 状态向量 + 文本描述 | 否，v0.2 |
| trainer | 事件数据集 | LoRA 适配器 | 是（只做个体层） |
| eval | 封存集、模型 | 准确率、校准度、消融表 | 是 |
| agents | 用户/研究者请求 | 预测、解释、问卷回答 | 是 |
| sdk | — | 外部 API 调用 | 否，v0.3 |

## 5. 数据库架构

结论：单机用 **PostgreSQL 16 + pgvector + TimescaleDB 扩展** 一个库搞定关系、向量和时序，原始帧放本地对象存储（MinIO 或文件夹），提取后按策略删除。Demo 甚至可以先用 SQLite + sqlite-vec，接口不变。

核心是 `decision_event`：每一行是一个“情境 → 选择集 → 行为”单元，它是训练、检索和评测的共同单位。

| 表 | 关键字段 | 作用 |
| --- | --- | --- |
| `device` | id, kind(desktop/android/ios), clock\_offset\_ms | 多设备时钟对齐 |
| `raw_capture` | id, device\_id, ts, kind(frame/ui\_tree/notification), blob\_uri, phash, deleted\_at | 原始数据索引，提取后置删除 |
| `context_event` | id, ts\_start, ts\_end, device\_id, app, event\_type, text, entities\_jsonb, redacted | 浏览、切换、通知等非决策事件 |
| `decision_event` | id, ts, device\_id, app, domain(消费/信息/表达/社交/娱乐/政治), context\_window\_id, choice\_set\_jsonb, action\_jsonb, exposure\_source(推送/推荐/主动), rationale\_text, rationale\_status(推断/经确认), split(train/val/sealed) | 训练主样本 |
| `state_sample` | ts, metric(hr/sleep/location\_type/…), value, z\_score | 时序，Timescale hypertable，以个人基线标准化 |
| `esm_response` | id, ts, prompt, answer\_jsonb, linked\_event\_id | 经验抽样，状态模型的监督标签 + 理由确认 |
| `self_report` | instrument(BFI/价值观/政治立场…), item, answer, ts | 量表，只做验证 |
| `embedding` | owner\_table, owner\_id, model, vector(1024) | pgvector，RAG 检索个人记忆 |
| `model_artifact` | id, layer(base/population/demographic/individual), base\_model, adapter\_uri, data\_cutoff, metrics\_jsonb | 分层 LoRA 版本管理 |
| `prediction_log` | id, model\_id, event\_id, predicted\_dist\_jsonb, created\_at, sealed\_hash | 预测封存，防止事后自我偏差 |
| `consent_policy` | scope, rule, created\_at | 哪些 app/联系人永不采集、哪些查询可对外开放 |

为覆盖风格、偏好和性格，再加三张表：

- `expression_event`：id, ts, app, audience\_type（家人/朋友/工作/公开/自己）, language, text\_redacted, reply\_context\_summary（对方内容只留摘要）, split。表达风格和社交模式的训练主样本。
- `preference_signal`：item\_type, item\_id, signal（点开/收藏/购买/跳过/取消关注）, strength, exposure\_source, ts。偏好排序任务的样本，同样区分推送与主动。
- `trait_probe`：instrument, item, twin\_answer\_dist, self\_answer, model\_id, ts。只用于性格与价值观的验证，不进入训练集。

三个关键设计：

- **`split` 按时间切分**，最后 1–2 周写入时标记为 `sealed`，训练代码层面禁止读取。
- **`exposure_source` 必填**，这是区分算法曝光和个人偏好的证据。
- **`prediction_log.sealed_hash`**：在你知道结果之前先写预测并哈希，事后比对，避免你看了预测后改变行为。

## 6. 后端服务与 API

结论：FastAPI 单体 + 一个异步 worker 足够支撑 Demo；推理服务独立成 vLLM 进程，便于热切换 LoRA。全部跑在本机 docker-compose 里，默认只监听 localhost。

| 服务 | 技术 | 职责 |
| --- | --- | --- |
| `api` | FastAPI + SQLAlchemy | 数据浏览、标注、训练任务、预测、Agent 入口 |
| `worker` | Arq（Redis 队列） | OCR/VLM 提取、脱敏、事件切分、嵌入、训练调度 |
| `inference` | vLLM（多 LoRA 热加载） | 分层模型推理，返回选项的 logprob 分布 |
| `ingest` | 轻量 HTTP 接收端 | 手机端经局域网/Tailscale 上传事件，端到端加密 |

主要接口（REST，OpenAPI 自动生成，SDK 由此生成）：

- `POST /ingest/{device}`：采集端上报事件批次
- `GET /events?domain=&from=&to=`：浏览、筛选事件
- `PATCH /events/{id}/rationale`：确认或修改推断的理由
- `POST /train/jobs`：启动某一层的 LoRA 训练，参数含 base 模型、数据截止日
- `POST /predict`：输入情境 + 选择集，返回 `{option: prob}` 分布和所用模型层
- `POST /survey`：输入问卷题目，返回孪生作答分布（研究者接口原型）
- `POST /agent/chat`：Agent 对话入口，SSE 流式返回
- `GET /eval/reports/{id}`：评测与消融结果

`/predict` 和 `/survey` 都返回**分布而不是单一答案**，并带 `layer` 参数，可以分别调用人口学层和个体层做对照。

## 7. AI Agent 设计

结论：Agent 分两类——**管线 Agent** 负责把数据变成高质量训练样本，**孪生 Agent** 负责对外扮演“你”。用 LangGraph 编排（状态机清晰、可断点续跑），工具统一以 MCP 协议暴露，这样孪生本身也能作为一个 MCP Server 被其他客户端调用。

| Agent | 触发 | 工具 | 产出 |
| --- | --- | --- | --- |
| 提取 Agent | 新帧入库 | 本地 VLM、OCR、app 规则库 | 判断是否为决策点，抽取选择集与行为 |
| 脱敏 Agent | 提取之后 | NER、人脸检测、联系人白名单 | 他人姓名/消息/人脸替换为占位符 |
| 追问 Agent | 不确定的决策点 | ESM 推送、`PATCH rationale` | 在当天向你提 1–3 个短问题，确认理由（主动学习） |
| 孪生 Agent | 用户或研究者提问 | `predict`、`memory_search`、`state_now` | 以你的身份回答，附概率与依据事件 |
| 评测 Agent | 训练完成 / 每周 | `eval.run`、`ablate`、读 `prediction_log` | 准确率、校准、消融报告 |

孪生 Agent 的推理流程：

1. 解析问题，识别领域（消费、信息、表达等）和选择集；开放问题先由模型生成候选选项。
2. `memory_search`：从 pgvector 检索最相似的历史决策事件（RAG，提供具体先例）。
3. `state_now`（可选）：读当前状态，例如睡眠不足、在通勤。
4. `predict`：个体层 LoRA 输出选项分布；同时调用人口学层，计算“你偏离同类人群”的部分。
5. 以受众和平台为条件，用你的口吻生成回答，标明置信度和引用的事件 id，低置信度时明确说“不确定”。

两条硬约束写进 Agent 的系统层，而不是靠提示词：对外查询只开放 `consent_policy` 允许的问题类型；外部调用只返回聚合或分布结果，不返回原始事件文本。

## 8. 基座模型选型与分层 LoRA

结论：孪生主干用 **Qwen3.5-9B-Base**，数据提取用 **Qwen3.5-4B**，升级路线是 Qwen3.5-27B / 35B-A3B 的 Base 版本。理由有三：Apache 2.0 许可最适合开源再分发；同时提供 Base 版本，可以绕开 RLHF 的“助手人格”；原生多模态且中文能力强，正好匹配你中英混合的截图数据。

| 用途 | 推荐模型 | 硬件 | 说明 |
| --- | --- | --- | --- |
| 孪生主干（个体层 LoRA） | [Qwen3.5-9B-Base](https://rits.shanghai.nyu.edu/ai/qwen-3-5-small-models-9b-parameters-that-beat-120b) | 单卡 24GB（3090/4090），QLoRA | 2026 年 3 月发布的小模型系列含 Base 版本，Apache 2.0 |
| 帧解析 / 事件提取 VLM | Qwen3.5-4B（指令版） | 约 8GB，M 系列 Mac 可跑 | 截图理解 + 结构化 JSON 输出，跑在采集机本地 |
| 升级主干 | [Qwen3.5-27B / 35B-A3B Base](https://rits.shanghai.nyu.edu/ai/qwen-3-5-medium-series-frontier-ai-that-fits-on-your-gpu) | 48GB+ 或租用云 GPU | 数据量足够、个体层收益饱和后再换 |
| 嵌入（RAG） | Qwen3-Embedding 或 bge-m3 | CPU 即可 | 多语言，用于检索相似历史决策 |
| OCR 兜底 | PaddleOCR | CPU/GPU | 中文优于 Tesseract；Android 端优先用无障碍服务，不需要 OCR |
| 对照基座 | 一个非中文主导训练的开源 Base 模型 | 同上 | 检验孪生的偏差有多少来自基座本身 |

分层训练顺序（每层一个 LoRA，只学相对上一层的偏离）：

1. **群体校准层**：用 WVS、ESS、ALLBUS、CGSS 的回答分布做分布匹配微调（SubPOP 思路），目标是 logprob 分布贴近人群分布，而不是单一答案。
2. **人口学层**：条件微调，输入“人口学画像 + 问题”，输出该人群的回答分布。
3. **个体层**：你的 `decision_event`、expression\_event 和 preference\_signal，全部文本化为补全格式（不用对话格式），多任务联合训练：选择预测（决策）、以受众为条件的续写（风格）、偏好排序（偏好）、下一事件预测（节律）；辅助任务为遮蔽模态预测和对比学习。按任务配比采样，防止数量最多的表达数据压过决策任务；必要时每个任务一个小 LoRA，再合并或路由。
4. **状态模型**（v0.2）：独立小模型，从生理/位置时序推断状态，输出作为个体层的输入文本。

Demo 阶段可以只做第 3 层：直接在 Base 上训个体 LoRA，与“Base + 人口学提示词”对照，先证明个体数据有增益。另外，Qwen3.6 / 3.8 的开源权重和 Base 版本状态仍在变化，正式开工前要在 Hugging Face 上确认一次。

### 追问组件：桌面伴侣

追问不再是推送问卷，而是常驻桌面角落的一个“孪生体”：会呼吸、眼睛跟随鼠标，有问题时轻轻跳动并亮起提示点，**你点它才展开问题**，不主动弹窗打断。[交互原型](https://claude.ai/artifact/TUA1vLqetSvbzVYmCKbxos)

| 时刻类型 | 触发 | 交互形式 | 写入 |
| --- | --- | --- | --- |
| 理由确认 | 犹豫后放弃、长时间比价 | 展示记录到的选择集 + 理由选项 + 曝光来源 | `decision_event.rationale` |
| 预测对赌 | 孪生对某个未来行为有预测 | 你和孪生各给概率，封存后到期揭晓 | `prediction_log` |
| 状态快照 | 长会议、深夜、运动后 | 二维情绪坐标点选 | `esm_response` |
| 矛盾追问 | 说法与行为不一致 | 选项含“两个都是真的我”，矛盾原样保留 | `expression_event` 关联 |
| 自我画像 | 孪生形成新的整体判断 | 五级“像不像我” + 可选更正 | `trait_probe` |

规则：每天最多 3 次；“稍后再问”保留、“这条别问”丢弃且不进训练；专注模式下孪生入睡，只排队不打扰；点孪生可查看并删除今天的回答。交流是双向的：点开孪生就是一个聊天窗口，你可以问它“我是什么样的人”“这个我会不会买”，它以第一人称回答、给出把握和依据，没学到的就直说；它的提问也以卡片形式出现在同一个对话里，回答后它会说出自己原本的猜测。拟人化体现在表情（好奇、思考、说话、开心、入睡）、可自定义的名字和随状态变化的一句话状态；但它始终说明自己是 AI 孪生，不假装是人。实现上用 Tauri 做透明置顶小窗，共用控制台的前端组件，经本地 API 读写；手机端用同样的卡片做通知。

## 10. Demo 范围与里程碑

结论：Demo（v0.1）约 6–8 周，只证明一件事——**在你自己的封存数据上，个体 LoRA 预测你的选择比“Base + 人口学提示词”更准**。状态模型、群体校准层、对外 API 都放到后续版本。

v0.1 的范围：电脑端（screenpipe）+ 一部 Android（或 iPhone 降级方案）+ 2–3 个平台的 GDPR 导出；决策领域先限定消费和信息选择两类，选择集最清楚；表达风格同步纳入，因为你自己发出的文字最容易采集、信号最干净。

1. **第 1 周 · 地基**：定 `schema` 事件模式，搭 docker-compose（Postgres + pgvector + Redis + API 骨架），申请平台数据导出。
2. **第 2–3 周 · 采集与提取**：desktop 采集器跑起来；Android 无障碍采集器 MVP；提取 Agent 把帧变成 `decision_event`；脱敏 Agent 上线。
3. **第 3–5 周 · 积累与审阅**：每天在控制台审阅决策点，追问 Agent 推送经验抽样；目标约 500–1000 个已确认决策点。
4. **第 5–6 周 · 训练**：时间切分，最后 1–2 周封存；QLoRA 训个体层；跑基线对照。
5. **第 6–7 周 · Agent 与前端**：孪生 Agent 接 `predict` + `memory_search`；时间线、审阅、对话三页可用。
6. **第 7–8 周 · 评测与发布**：解封评测，写消融报告；整理 README、示例数据（合成数据，不放你的真实数据），在 GitHub 公开 v0.1。

后续版本：v0.2 加状态模型和可穿戴数据；v0.3 加群体校准层、人口学层和研究者 SDK；v0.4 做多人联邦（每人本地训练，只上传聚合结果），也就是 AION 平台的接入点。

## 11. 评测、隐私与开源治理

**评测。** 主指标是封存集上的选择预测准确率和对数损失（分布质量），外加校准曲线；对照组依次为随机、频率基线（经典选择模型）、Base + 人口学提示词、个体 LoRA、个体 LoRA + RAG。消融逐个去掉模态和 RAG，回答“哪种数据最值得采集”。风格用熟人盲测和风格计量分类器（能否把孪生文本与你的真实文本区分开）；偏好用排序指标；性格与价值观让孪生作答量表，与你本人间隔数周后的作答比对。量表和访谈只用于外部效度检查。

**隐私与安全。**

- 原始帧提取后默认 24 小时内删除，只保留结构化事件；数据库与磁盘全盘加密。
- 他人内容本地脱敏后才进入训练；默认屏蔽银行、医疗、密码管理器等敏感 app。
- 模型权重与数据同等对待：不上传、不分享；对外接口只返回分布或聚合结果，并设查询频率上限，防止通过反复提问套出隐私。
- 录音在德国涉及刑法第 201 条风险，v0.1 不采集声音。

**开源治理。**

- 代码用 Apache 2.0（与基座许可一致），文档和事件模式另附数据伦理说明。
- 仓库里只放合成示例数据和数据生成器，绝不放任何真实个人数据。
- 插件接口（采集器、解析器、模型后端）写清规范，方便社区贡献新平台的采集器和 GDPR 导出解析器——这是最容易吸引贡献者的部分。
- 开源核心与 AION 的边界：本地采集、处理、训练、单人孪生全部开源；多人聚合、代表性加权、研究者市场作为商业层。

## 12. 最终愿景：Mirrorself 平台

结论：本文档前 11 章描述的本地单人孪生，最终会成为一个三方平台里的“节点”。平台做两件事：通过 Hub 分发基座、共享层和部署教程；通过研究网关让研究者调用成千上万个个人孪生做调查和实验。平台自身不托管任何个人模型或数据。这一章是愿景和完整的工程构思，不属于 Demo 范围；实施顺序见 12.5。

### 12.1 平台组成

&#91;embedded content: Mirrorself 平台架构 · 三方与数据流向\]

个人节点就是第 3 章的本地系统加上一个“本地执行器”插件；平台侧只有四个服务，任何一个都可以被自建替代。

### 12.2 Hub：模型与教程分发

Hub 只分发可共享的东西：基座索引、共享层、工具和教程。个体层和任何个人数据永远不经过平台。

| 分发物 | 内容 | 格式 |
| --- | --- | --- |
| 基座索引 | 推荐基座的版本、哈希、许可；不重复托管基座，指向官方仓库 | 版本清单 JSON |
| 群体层 LoRA | 用 WVS、ESS 等校准，Track P 与 Track S 各一份 | safetensors + GGUF |
| 人口学层 LoRA | 按国家/地区：德国（ALLBUS/GLES）、中国（CGSS）、跨国 | safetensors + GGUF |
| 提取与脱敏配置 | VLM 提示词、各 app 规则库、NER 模型 | YAML + 权重 |
| 合成示例孪生 | 一个合成人物的完整数据和训练好的个体层，用来体验全流程 | 数据包 + 适配器 |
| 采集器与解析器 | 设备采集器、各平台 GDPR 导出解析器 | Python 包 / APK |

共享层的发布流水线：

1. **训练**：由维护者用公开调查数据训练；后期也可由志愿节点联邦训练产出。
2. **自动评测**：校准报告；偏差审计（各人群子组的误差是否有系统差异）；记忆泄漏测试（成员推断攻击，确认没有记住训练数据中的个人信息）。
3. **模型卡**：数据来源、基座版本、适用人群、已知偏差、许可。
4. **签名**：用 Sigstore 签名，写入版本清单。
5. **发布**：推到 Hugging Face 组织，并镜像到 ModelScope 方便中国用户；安装器按清单拉取并校验哈希。

部署与升级：

- `mirrorself init`：检测显卡和内存，按档位选择基座（约 8GB 用 4B 量化推理；24GB 用 9B + QLoRA 训练；48GB 以上用 27B 或 35B-A3B），拉取 docker-compose，生成本地加密密钥。
- `mirrorself migrate`：基座或共享层升级后，个体层需要重训；迁移工具先在封存集上比较新旧个体层，确认不退步才切换。
- 兼容性矩阵：CI 自动测试“基座版本 × 硬件档位 × 操作系统”，结果公开在文档站。

文档站（Docusaurus，中英双语）的结构：快速开始（30 分钟用合成数据跑通）；核心概念（双轨、分层、信息集隔离）；采集器配置（按设备）；训练教程（Track P 与 Track S 分开）；隐私与安全；加入研究网络；开发者指南（插件接口、贡献流程、发布共享层的规范）。

### 12.3 研究网关：联邦执行

研究者从不接触任何一个孪生。研究以签名任务包的形式下发，由各个本地节点执行，平台只回收经过隐私保护的聚合结果。

一项研究的完整流程：

1. 研究者在网关注册，提交研究方案：目的、问卷或实验设计、目标配额、伦理审查证明、使用的轨道（P 或 S）。
2. 网关审核：过滤禁止用途（针对个人的说服优化、政治精准投放、重新识别个人），检查隐私参数是否合规。
3. 协调器生成签名任务包，进入任务队列。节点通过 HTTPS 长轮询主动拉取，本地不开放任何入站端口。
4. 节点本地校验：是否符合持有人的同意策略和话题黑名单、剩余隐私预算、调用频率；通过后在桌面伴侣里请持有人逐项授权。
5. 授权后本地孪生作答，输出加入本地差分隐私噪声，再经安全聚合上传，服务器只能看到汇总值。
6. 达到最小群组规模（例如 50 个节点）后，聚合服务做事后加权，生成结果和代表性报告。
7. 可选：邀请一部分持有人本人作答，计算孪生与真人的一致率，随结果一起公开。

任务包结构：研究 id、题目或刺激材料、允许的轨道、输出格式（只能是选项分布或数值）、隐私参数 ε、最小群组规模 k、过期时间、网关签名。节点拒绝任何未签名或参数越界的任务。

| 研究类型 | 默认轨道 | 返回给研究者 |
| --- | --- | --- |
| 问卷调查 | P | 每题答案分布与置信区间 |
| 选择实验 / 联合分析 | P | 属性效用估计 |
| 信息曝光 A/B | P（必要时 S） | 组间分布差异 |
| 纵向追踪 | P | 同一批节点在多个时间点的分布序列 |
| 开放式访谈 | S | 主题层面的聚合摘要，不返回任何原文 |
| 多智能体社会模拟 | S | 群体动态指标（扩散速度、极化程度等） |

| 接口 | 作用 |
| --- | --- |
| `POST /studies` | 提交研究方案与材料（可导入 Qualtrics QSF、LimeSurvey） |
| `POST /studies/{id}/fielding` | 设定配额、预算、隐私参数，开始投放 |
| `GET /studies/{id}/status` | 已授权、已完成的节点数，配额缺口 |
| `GET /studies/{id}/results` | 加权分布、置信区间、代表性报告 |
| `POST /studies/{id}/validation` | 申请真人校验子样本 |
| `GET /registry` | 公开的研究登记表：谁在研究什么 |

隐私与代表性的工程要点：

- **隐私预算账本**：每个节点每年有总 ε 上限，每次作答扣减，耗尽后自动退出研究；账本在本地，网关只看到“是否还有余额”。
- **安全聚合**：用 Flower 框架的安全聚合协议，单个节点的回答在服务器端不可见。
- **抽样与加权**：节点自愿声明粗粒度人口学信息（年龄段、性别、地区、教育），只用于配额；结果用 raking 对齐人口普查边际分布；代表性报告列出覆盖缺口和设计效应。
- **技术栈**：网关用 FastAPI + Postgres；协调与聚合用 Flower；身份用 OIDC，节点密钥绑定设备；研究者 SDK 提供 Python 和 R 两个版本，结果直接返回 pandas / data.frame。

### 12.4 治理与商业模式

- **持有人控制**：逐项研究授权，随时撤回；在桌面伴侣里能看到自己的孪生被问过什么、回答了什么、赚了多少。
- **研究者准入**：必须提交伦理审查证明；所有研究进入公开登记表；禁止用途清单写进服务条款和网关审核规则。
- **防作弊**：一人一节点，注册时通过第三方身份核验，平台只保存核验通过的凭证、不保存证件号码；孪生质量分来自真人校验子样本，质量过低的节点暂停参与；检测批量生成的可疑节点。
- **法律角色**：研究者、平台、节点持有人在 GDPR 下分别是什么角色（控制者、处理者，或本地处理是否适用家庭活动豁免），需要正式的法律评估后再定。
- **开源边界**：本地节点、Hub、任务包协议、研究者 SDK 全部 Apache 2.0 开源，任何人都能自建网关；托管的研究网关、代表性加权服务、研究者市场作为 AION 的商业层。持有人按完成的任务获得分成。

### 12.5 从 Demo 到平台的演进

每个阶段设一个通过门槛，不过门槛就不进入下一阶段：

1. **v0.1 Demo（N=1）**：Track P 完整实现，Track S 只做风格续写和伴侣对话。门槛：个体层在封存集上显著优于“Base + 人口学提示词”。
2. **v0.2 完整双轨**：Track S 完整实现，加入状态模型和可穿戴数据。门槛：熟人盲测的区分率接近随机；一周模拟轨迹与真实轨迹的分布距离低于预设阈值。
3. **v0.3 首次分发**：发布群体层、人口学层、合成示例孪生和文档站。门槛：外部用户按教程 30 分钟内跑通。
4. **v0.4 联邦试点**：10 到 50 名志愿者组成网络，内部复现一项经典调查（如 ESS 的部分题目）。门槛：聚合结果与真人调查的差距在可接受范围内，且零隐私事故。
5. **v1.0 研究网关开放**：公开研究者接口、SDK、收益分成。门槛：通过外部安全审计和法律评估。
