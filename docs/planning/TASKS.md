# 个人认知孪生：v0.1 任务清单

更新日期：2026-11-10。依据仓库《个人认知孪生（开源）工程方案 v0.1》和当前讨论整理。

目标：持续记录自己的数字生活，把记录整理成可靠的经历，用这些经历训练模型，最后验证它是否更了解自己的选择。

工作顺序：持续采集 → AI 整理事件 → 人工审阅 → 制作训练数据 → 训练 → 封存评测 → 演示与发布。

本清单是执行规划，未勾选的任务均未完成。负责人暂按角色划分，具体执行者在派发任务时填写。先完成电脑端最小闭环，再扩展手机和其他数据源；持续采集与分批训练分开进行。

## 0. 开工准备

- [ ] T00-1 确认首台采集电脑的系统、内存、显卡，以及后续手机型号。负责人：项目统筹 + 项目持有人。
- [ ] T00-2 选择首批场景：消费选择、信息选择；列出允许采集和禁止采集的应用。负责人：项目统筹 + 项目持有人。
- [ ] T00-3 明确本地提取和训练所用硬件，核实候选模型的官方权重、许可与运行条件。负责人：模型工程。
- [ ] T00-4 搭建仓库目录、开发环境、合成示例数据和基本运行说明。负责人：工程基础。
- [ ] T00-5 定义统一事件格式：时间、设备、应用、看到的选项、实际操作、曝光来源、证据引用、确认状态。未知信息明确标记，不猜测。负责人：数据架构。
- [ ] T00-6 提前确定评测规则：时间切分、主指标、对照模型和通过标准，正式评测前冻结。负责人：评测。

完成标准：执行者知道在哪台设备、采集哪些场景、记录哪些字段；可以用合成数据运行基础环境。硬件和具体平台未确定前，不锁死模型或采集实现。

## 1. 先做出能持续工作的电脑采集器

负责人：采集工程。依赖：T00-1、T00-2、T00-4、T00-5。

- [ ] T01-1 验证 screenpipe 在目标电脑上的适用性，决定接入方式。
- [ ] T01-2 实现定时截图、窗口切换记录；页面变化触发按可用能力接入，截图频率可调整。
- [ ] T01-3 能直接读取网页或界面文字时优先读取，截图作为补充，并记录数据来源。
- [ ] T01-4 为记录附上时间、应用和设备信息，对重复画面去重。
- [ ] T01-5 提供开始、暂停、恢复和退出；敏感应用在采集前排除，默认不录音。
- [ ] T01-6 本地保存待处理记录，支持重启恢复、失败重试和磁盘空间限制。
- [ ] T01-7 记录采集延迟、遗漏、CPU/内存占用与每日存储量。

完成标准：在目标电脑完成一次正常工作日试运行，产出连续且可追溯的记录；暂停和排除规则有效；重启可继续工作，并有资源占用报告。

## 2. 让 AI 把记录整理成经历

负责人：数据处理与模型提取。依赖：统一事件格式；可先用合成截图开发，接入依赖阶段 1。

- [ ] T02-1 接入本地 OCR / 多模态模型，识别图片中的文字、选项和操作线索。
- [ ] T02-2 按时间把连续截图和界面事件组合，避免把每张截图当成独立决策。
- [ ] T02-3 输出结构化事件：当时在做什么、看到哪些选项、发生了什么操作、曝光从哪里来。
- [ ] T02-4 区分事实、模型推断与未知；不能从“没有购买”直接推断“嫌贵”。
- [ ] T02-5 保存证据引用、提取版本和不确定项，失败任务可重试，重复处理不重复入库。
- [ ] T02-6 脱敏他人信息，处理完成的原始帧默认 24 小时内删除；失败记录同样设保留上限并报告状态。
- [ ] T02-7 用人工标注的小样本检查选项、操作和事件时间是否提取正确，记录错误类型。

完成标准：能把一段连续操作整理成可检查的事件，例如“查看三款耳机，把 B 加入购物车，暂未下单”；缺失信息不会被编造，不确定事件进入审阅队列。

## 3. 做一个可以查看和纠正的经历库

负责人：后端与前端。依赖：统一事件格式；可与阶段 1、2 并行开发。

- [ ] T03-1 建立本地事件存储和 API，服务默认只监听本机。
- [ ] T03-2 做时间线：按日期、应用和领域查看事件。
- [ ] T03-3 做审阅界面：修正选项、实际行为、曝光来源；确认或否定推断的理由。
- [ ] T03-4 区分未审阅、已确认、已排除的数据，保留修改记录。
- [ ] T03-5 做隐私控制：采集开关、排除列表、原始截图删除状态、删除事件。
- [ ] T03-6 删除或排除事件后，使相关训练数据索引失效；说明已训练模型需要重训才能移除影响。
- [ ] T03-7 优先展示不确定事件；需要追问时每天最多三次，用户主动打开后查看。
- [ ] T03-8 用真实采集数据贯通“采集 → 整理 → 查看 → 纠正 → 保存”。

完成标准：项目持有人可以独立浏览当天经历，纠正一条错误事件，排除不想用于训练的记录，确认修改已保存。

**第一个里程碑：阶段 1–3 跑通。此时已有持续产出可审阅经历的系统，可以开始日常积累数据。**

## 4. 把经历变成模型的练习题

负责人：数据集工程 + 评测。依赖：阶段 3、T00-6。

- [ ] T04-1 制作选择预测样本：题目是行动前的情境和选项，答案是实际行为。
- [ ] T04-2 检查题目不含后续操作、事后理由或未来信息，避免提前透露答案。
- [ ] T04-3 将不完整选择集、未知曝光来源等质量问题单独统计，制定纳入或排除规则。
- [ ] T04-4 按时间划分训练、验证和封存数据，相关连续事件不能跨集合泄漏。
- [ ] T04-5 在数据读取层阻止训练访问封存集，检索和统计特征也遵守时间截止规则。
- [ ] T04-6 记录数据集版本、来源、样本数量和排除原因。
- [ ] T04-7 如学习表达风格，使用本人实际写出的文字单独制作续写样本；量表回答不进入训练。
- [ ] T04-8 持续积累并审阅数据，以原方案的 500–1000 个已确认决策点为目标；按实际质量和数量调整周期。

完成标准：能复现同一份数据集，能追溯每条样本，封存数据不会进入训练；样本不足时明确报告，不用重复数据凑数。

## 5. 先跑对照，再训练个人模型

负责人：模型训练。依赖：阶段 4 和可用训练硬件。

- [ ] T05-1 跑通随机、频率/经典选择模型、Base + 人口学提示词等对照。
- [ ] T05-2 在选定基座上用 QLoRA 训练个人适配层，优先学习选择预测。
- [ ] T05-3 保存训练配置、数据版本、随机种子、模型版本与日志。
- [ ] T05-4 只用训练集和验证集调整模型，不使用封存结果反复调参。
- [ ] T05-5 提供本地预测接口：输入情境和选项，返回各选项的概率及模型版本。
- [ ] T05-6 如加入历史检索，单独比较“有检索”和“无检索”的效果，并检查时间边界。

完成标准：同一输入能分别调用对照模型与个人模型，输出有效概率分布；训练过程可复现，个人数据与权重保留在本地。

## 6. 验证模型到底有没有学到你

负责人：评测。依赖：阶段 5，且评测规则已冻结。

- [ ] T06-1 在统一封存集上比较各模型，输出准确率、对数损失、Brier 分数和校准结果。
- [ ] T06-2 按消费、信息选择等场景分开报告，说明样本数和不确定性。
- [ ] T06-3 按预先制定的方法检验个人模型的提升是否可靠；不能只挑表现好的例子。
- [ ] T06-4 做必要消融，判断个人训练和历史检索分别带来多少收益。
- [ ] T06-5 如做未来行为预测，在结果发生前保存预测、时间和哈希，再与实际结果对比。
- [ ] T06-6 写出结论：有效、证据不足或没有改善，以及下一轮需要补什么数据。

完成标准：有可复现的对照报告。工程流程跑通与模型效果达标分别记录；解封后的数据不再作为下一轮调参的独立封存证据。

## 7. 做成可演示、可安装的 v0.1

负责人：产品前端 + Agent 集成 + 工程发布。依赖：阶段 3、5、6。

- [ ] T07-1 接入孪生对话，以个人口吻回答，并展示预测概率与可用依据；不确定时明确说明。
- [ ] T07-2 做基础桌面伴侣入口，共用审阅和对话卡片；主动点击才展开，支持稍后再问和丢弃。
- [ ] T07-3 若实现模拟者记忆，限制其只能读取当时之前本人可见的内容，不读取未来或统计画像。
- [ ] T07-4 补齐本地安装说明、合成示例数据和从采集到评测的操作指南。
- [ ] T07-5 检查发布内容不含个人数据、私人模型权重和敏感配置。
- [ ] T07-6 发布 v0.1，并如实说明支持的设备、已验证能力和评测局限。

完成标准：另一位开发者能按说明用合成数据跑通流程；项目持有人能使用真实数据版本完成演示。

## 后续扩展队列

- [ ] 接入 Android 或 iPhone 降级采集方案，并处理跨设备时间对齐。
- [ ] 根据实际平台接入 2–3 个数据导出解析器；历史导出可在电脑闭环稳定后提前启动。
- [ ] 增加完整的风格续写评测、模拟者训练和长时程模拟。
- [ ] 增加状态模型、可穿戴数据、群体层和人口学层。
- [ ] 推进研究者 SDK、Hub 和多人研究网络，另立任务清单。

这些项目保留原工程方案的方向，按阶段推进。手机和导出仍是原定 v0.1 的扩展范围；如发布前未完成，应明确标注实际范围。

## 如何分工与更新

项目统筹维护范围、依赖和验收记录；执行者领取具体任务编号。每次派发写明负责人、输入、交付文件、依赖和完成标准。验收通过后才勾选，并附提交或报告链接。

当前最先派发：T00 开工准备 → T01 电脑采集。事件格式确定后，T02 提取管线与 T03 审阅界面可以并行；训练必须等待可用数据，不能按日历直接跳过数据质量门槛。

项目持有人主要参与：确认设备和采集范围、授权本机采集、日常审阅少量不确定事件、提供真实选择结果、体验最终演示。工程执行者负责实现与技术验证。
